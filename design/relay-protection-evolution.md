# 继电保护架构演进文章与动画设计

## 目标

用一篇可离线阅读的文章和一份可交互的原版HTML动画，解释继电保护从机电式到虚拟协同保护的演进。读者应能回答三个问题：每一阶段怎样完成“测量—判断—跳闸”，为什么上一阶段需要演进，以及下一阶段改变的是算法、信息范围还是硬件部署。

## 内容边界

- 采用五阶段叙事：机电式、静态电子式、微机式、数字网络化、虚拟化与智能协同。
- 明确前四阶段是常见技术演进划分；“第五代”是本文对正在形成的技术方向的概括，不是IEC或IEEE统一命名。
- 不把继电保护装置与断路器混称为“保护开关”：保护系统判断，断路器切断一次电流。
- 不把AI描述为关键主保护的唯一跳闸判据；本地确定性保护和独立后备始终保留。

## 分层与单向依赖

1. **文章层**：`docs/knowledge/relay-protection-evolution.md`，包含完整文字、简化文本拓扑、来源和动画降级说明。
2. **演示层**：`docs/public/demos/relay-protection/relay-protection-generations.html`，作为五代控制流程图、步骤数据和动效时序的唯一权威实现。
3. **导航层**：`docs/.vitepress/config.mts`和`docs/index.md`只提供入口，不反向承载文章内容或动画逻辑。
4. **发布层**：现有VitePress构建和GitHub Pages工作流只消费前三层，不新增运行时服务。

### 禁止依赖

- 动画不得依赖站点私有数据、登录态或外部API。
- Markdown不得复制第二套JavaScript步骤数据。
- 导航配置不得决定动画内部状态。
- AI辅助、云端分析和广域应用不得进入毫秒级唯一跳闸链路。

## 动画交互

- 顶部选择五个阶段；每次只展示一代的控制链，降低认知负担。
- 提供播放、暂停、上一步、下一步和复位。
- 当前节点、已完成节点和等待节点同时使用文字、位置与颜色表达。
- 每一步显示一条简短解释；动画结束停留在完整动作结果。
- 移动端将横向链路折叠为蛇形多行结构；遵守`prefers-reduced-motion`。

## 验收

- 五代均能从第一步推进到断路器分闸，并能复位。
- 第四代必须出现MU、SV、保护IED、GOOSE和智能终端。
- 第五阶段必须同时出现PIU、冗余网络、边缘IED、虚拟IED集群和协同决策。
- 文章在动画加载失败或JavaScript关闭时仍能解释每代完整链路。
- 桌面和375px移动宽度均无横向溢出，深浅主题可读。
- 构建、链接、脚本语法和Git差异检查通过。

## 兼容与回滚

- 新路由和静态资源不修改既有文章URL或组件接口。
- 回滚本次提交即可完整移除文章、动画和三个入口。
- GitHub仓库保存正文、动画、设计和发布配置；在干净环境执行`npm ci && npm run check`可验证恢复。
