# 软件定义 PAC 文章设计

## 目标与范围

把现场资料中的软件定义保护、自动化与控制（PAC）信息整理为一篇可公开阅读、可追溯的 EnergyBook 行业洞察。文章解释概念、架构、厂商路线和落地门槛，不做厂商性能排名，也不把展会演示等同于规模化运行证据。

## 内容分层

1. **概念层**：区分功能独立于硬件（FIH）这一目标与虚拟机、容器、服务器集群等实现手段。
2. **架构层**：用一张原创图说明过程接口、实时平台、PAC 应用、工程与运维的单向依赖。
3. **产品层**：分别说明 Siemens Energy 与 GE Vernova 的公开路线，厂商量化指标均标为厂商主张。
4. **交付层**：归纳实时性、高可用、IEC 61850 工程、安全、测试和生命周期要求。
5. **证据层**：优先引用厂商、CIGRE 和 LF Energy 一手来源，并明确现场观察与公开资料的边界。

## 公开素材策略

- 不将现场拍摄的厂商展板、演示屏和演讲页复制到公开仓库。
- 新增一份 Codex 原创自包含 HTML/SVG 架构图，版本化保存在 `docs/public/demos/software-defined-pac/`。
- Markdown 正文完整表达图中结论，图形不是理解文章的唯一入口。

## 公共契约与禁止依赖

- 文章路由：`/insights/software-defined-pac-architecture`
- 图形路由：`/demos/software-defined-pac/architecture.html`
- Markdown 只通过 iframe 引用图形，不依赖站点私有运行时状态。
- 图形不加载外部脚本、字体或数据，不复制厂商视觉资产。
- 不引入依赖，不修改既有文章路由。

## 验收

- `npm run check` 与 `git diff --check` 通过。
- 生成文章 HTML、首页、导航和 sitemap 均包含新路由。
- 桌面和移动视口无页面级横向溢出，浅色与深色模式均可读。
- iframe 有标题、懒加载、沙箱和文字降级；减少动态效果偏好得到尊重。
- 主要外链可访问，量化数据的归属清楚。

## 回滚

删除文章、原创图形、首页卡片和两处导航项即可回滚。本功能没有数据库、依赖或既有 URL 迁移。
