# 批阅来源策略

## 目标

让身份网关和受限执行器使用同一份部署来源配置，避免正式域名变更后只更新其中一层。

## 分层与契约

1. **策略层**：`review-policy.mjs` 负责解析逗号分隔的来源列表，并根据显式传入的 `Set` 校验 `siteOrigin`。
2. **API 层**：`review-api-server.mjs` 在服务启动时从 `REVIEW_ALLOWED_ORIGINS` 构建集合，注入负载校验。
3. **Runner 层**：`review-runner.mjs` 在提交 Cloud 任务前使用同一环境变量再次校验，保留纵深防御。
4. **网关层**：`review-gateway.mjs` 继续使用 `REVIEW_ALLOWED_ORIGINS` 约束 OAuth 返回地址、CORS 和批阅转发。
5. **部署层**：网关与执行器的仓库外环境文件必须持有相同的正式来源列表。

## 默认行为

- 未配置 `REVIEW_ALLOWED_ORIGINS` 时只允许本地预览来源，避免将某个真实部署域名写入公共策略或测试夹具。
- 空值会被忽略，来源必须精确匹配；不做子域、通配符或前缀匹配。
- 实际环境值和凭据只保存在仓库外配置中。

## 验收

- 注入的允许来源可通过策略与 API 校验。
- 未知来源在任何一层都不能创建任务。
- 本地预览仍可用于无生产凭据测试。
- 生产验证使用故意无效的业务负载：响应必须越过来源校验，但不得创建 Cloud 任务。

## 回滚

恢复上一版自动化文件和执行器环境文件备份，重启执行器；网关、n8n 工作流和前端负载协议无需回滚。
